jykj_ocr

多引擎 OCR 服务 —— 本地 RapidOCR(离线)+ 多模态 OCR 大模型(硅基流动 / 任意 OpenAI 兼容端点),策略层重试编排,提供 CLI、Python API 与 FastAPI HTTP 接口。

引擎类型API Key默认模型
rapidocr本地 ONNX无需—
siliconflow远程多模态必需PaddlePaddle/PaddleOCR-VL-1.5
multimodal远程多模态必需由 config 指定(回退 PaddleOCR-VL-1.5)

远程引擎统一走 OpenAI 兼容协议(POST /chat/completions),只依赖 requests,不引入 openai SDK。

引擎使用策略

配置固定默认策略,单次请求可用 strategy_name(CLI --strategy-name / API 参数 / HTTP 表单或 JSON 字段)一次性覆盖,不改动服务端配置。

顺序预设 seq*(走 StrategyEngine,按序尝试,首个命中即返回)

预设引擎范围重试判定阅读顺序重排适用场景
local仅本地(rapidocr 家族)no_text—离线、隐私敏感、批量低成本
vl仅远程 VL 大模型no_text—版面复杂、手写、表格
seq全部启用引擎按序回退no_text—通用生产链路
seq-any同 seq + 窜行降级any✅盖章/倾斜导致 rapidocr 窜行
seq-low_conf全部启用引擎low_confidence—低置信度自动降级
seq-line_overlap全部启用引擎line_overlap—窜行时自动降级
fallback同 seqno_text—legacy 别名(回退链)
quality同 seq-anyany✅legacy 别名(窜行降级+重排)

最佳预设 bestof*(走 BestofEngine,所有引擎各跑一次,按评分选最佳)

预设评分函数适用场景
bestof / bestof-smart置信度×100 − 窜行 + 文本长度 + **语义流畅度**综合最优,**推荐**
bestof-fastest耗时(elapsed_ms)最低追求速度
bestof-confidence平均置信度最高追求质量
bestof-longest文本最长追求完整性
bestof-fluency短语密度 + CJK 标点 − 单字碎片惩罚追求"读起来像人话",对比本地碎片化 vs VL 连贯结果
bestof:<mode>同以上任意 mode冒号语法别名

bestof-fluency:短语越长越连贯(+15),有标点更像自然语言(+5),单字/短词碎片扣减(上限 −25)。兰亭序实测 rapidocr fluency≈−23,siliconflow≈+15。

优先级:单次请求 strategy_name > POST /config 运行时覆盖 > config.yaml。新引擎注册即被预设识别,远程侧用 JYKJ_OCR_REMOTE_ENGINES 标记。

核心特性

统一端点

设一对 OPENAI_API_KEY/OPENAI_BASE_URL 即可指向任意平台,换平台不改代码。

命名策略预设

local/vl/seq*/bestof*/fallback/quality 四套预设,配置固定默认、请求可一次性临时切换;底层支持 line_overlap/any 窜行降级与 bestof-fluency 语义流畅度择优。

引擎可扩展

新引擎注册即被预设识别;JYKJ_OCR_REMOTE_ENGINES 一键把新厂商划入远程 VL 侧。

运行时配置

POST /config 热改模型/引擎/策略,不重启;线程安全,不回显 key 明文。

惰性注册

import jykj_ocr 不加载 PIL/rapidocr/openai,引擎按需 import。

快速开始

# 安装(自包含 requirements.txt)
pip install -r requirements.txt

# 配置远程引擎(换平台只改这两个变量)
export OPENAI_API_KEY=sk-xxx
export OPENAI_BASE_URL=https://api.siliconflow.cn/v1

# CLI 识别
python -m jykj_ocr image.png --engine siliconflow --format json

# 一次性命名预设(窜行降级 + 阅读顺序重排)
python -m jykj_ocr stamp.png --strategy-name quality

# 启动 HTTP 服务
python -m jykj_ocr serve --port 8000

HTTP 接口一览

方法路径说明
GET/health健康检查
GET/engines可用引擎列表 + 配置顺序
GET/presets全部命名策略预设(评分模式/重试判定/引擎范围)
GET/config当前配置(不回显 key)
POST/config运行时覆盖配置
DELETE/config清除运行时覆盖
POST/ocr上传图片/PDF 识别(multipart)
POST/ocr/text按图片 URL 识别(JSON)
POST/ocr/{preset}路由即策略:多部件上传(预设=引擎或策略名)
POST/ocr/{preset}/text路由即策略:按图片 URL(JSON)

实测状态

  • 三引擎在 tests/兰亭序.jpeg(750×1390 中文古文)上全部跑通
  • rapidocr 166 区域,置信度 0.97+,离线可用
  • siliconflow / multimodal 均返回完整全文
  • 七类命名预设(local/vl/seq*/cascade*/bestof*)在 http://192.168.0.81:8000 实测通过,未知名称返回 400 并列出可选值
  • GET /presets 返回全部 17 个预设 + bestof:<mode> 别名,含评分模式/重试判定/引擎范围/最大重试次数
  • /docs 全部 10 个操作按"OCR 识别"/"配置与状态"两组分类展示
  • 便捷路由 /ocr/{preset} / /ocr/{preset}/text(路由即策略)已上线,新引擎/新预设无需改路由
  • /ocr/{preset} 支持 retry_mode / score_mode / max_retries 三旋钮,单次请求覆盖预设默认
  • cascade* 家族:被 reject 的尝试立刻降级下一引擎,不重试同一引擎
  • 所有引擎统一走 BaseEngine.recognise 的墙钟超时(rapidocr 与远程),默认 120s,可用 EngineConfig.timeout 覆盖,timeout<=0 关闭
  • pytest 离线测试基线 173 passed
  • GET /config 实测 key_leaked=False
