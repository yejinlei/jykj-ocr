jykj_ocr

多引擎 OCR 服务 —— 本地 RapidOCR(离线)+ 多模态 OCR 大模型(硅基流动 / 任意 OpenAI 兼容端点),策略层重试编排,提供 CLI、Python API 与 FastAPI HTTP 接口。

引擎使用策略

配置固定默认策略,单次请求可用 strategy_name(CLI --strategy-name / API 参数 / HTTP 表单或 JSON 字段)一次性覆盖,不改动服务端配置。yaml 里的 strategy.name 不生效——它只是文档字段,预设只能由接口应用;yaml 中真正生效的只有 bestof_mode(触发 BestofEngine)、max_retries、retry_mode、min_confidence,「只用本地/只用远程」靠条目里的 enabled: false。

顺序预设 seq*(走 StrategyEngine,按序尝试,首个命中即返回)

预设引擎范围重试判定阅读顺序重排建议模型 / 场景
local仅本地(rapidocr 家族)no_text—只能有 rapidocr。**离线 / 隐私 / 批量化**
vl仅 1 条远程 VL(config 里第一条已启用的)no_text—PaddleOCR-VL-1.5 或 Qwen3-VL-30B。**本地必然烂的图**:手写、盖章、拍照倾斜、表格
seq全部启用引擎no_text—rapidocr → 快 VL。**通用生产默认**
seq-any同 seq + 窜行降级any✅同上。**盖章 / 倾斜 / 双栏**导致 rapidocr 窜行
seq-low_conf全部启用引擎low_confidence—阈值默认 0.7(可 POST /config 运行时改)。**模糊 / 低对比度 / 小字**
seq-line_overlap全部启用引擎line_overlap—只看窜行,不看置信度。**只关心版面顺序**
fallback同 seqno_text—legacy 别名(等同 seq)
quality同 seq-anyany✅legacy 别名(等同 seq-any:窜行降级 + 重排)

建议的引擎顺序:rapidocr 放第一位(命中成本 0)→ 快远程(PaddleOCR-VL-1.5,~3–5s)→ 慢远程(Qwen3-VL-30B,~12s;或 8B 省 token 兜底)。不要把代码/对话 Agent 模型(Kimi-K2.7-Code / GLM-4.5V 一类)当常规条目 —— 实测 140s+ 且带幻觉前缀。

级联预设 cascade*(与 seq* 同一个 StrategyEngine,唯一区别 max_retries=0)

预设retry_mode建议模型 / 场景
cascadeno_text同 seq,但被 reject 立刻换引擎,不重扫同一张
cascade-low_conflow_confidence同 seq-low_conf
cascade-line_overlapline_overlap**快速兜底链**:本地窜行就立刻上远程。实测比 seq-line_overlap 快 ~9s(11.0s vs 20.4s,差出的就是一次 rapidocr 重跑)

选 seq* 还是 cascade*:结果可能受网络抖动 / 限流影响(远程偶发空)→ seq*; 结果取决于图片本身(盖章窜行再扫一遍还是窜行)→ cascade*。

最佳预设 bestof*(走 BestofEngine,所有引擎各跑一次,按评分选最佳)

预设评分函数建议模型 / 场景
bestof / bestof-smart置信度×100 − 窜行 + 文本长度 + **语义流畅度**rapidocr + 快 VL。**通用质量最优,推荐首选**,自动规避碎片化输出
bestof-fastest耗时(elapsed_ms)最低⚠️ 比的是本次耗时,远程抖动时赢家会变。要稳定走本地请用 local
bestof-confidence平均置信度最高建议 rapidocr 做对照。**逐字准确**,需原文核对
bestof-longest文本最长⚠️ 陷阱:碎片化输出也可能很长。要"不漏字"请配 smart
bestof-fluency短语密度 + CJK 标点 − 单字碎片惩罚建议 Qwen3-VL-30B(自动分段)。**追求"读起来像人话"**
bestof:<mode>同以上任意 mode冒号语法别名(仅 HTTP / Python,CLI 不支持)

成本警告:BestofEngine 是串行的,3 个引擎最坏耗时 = 3 × timeout。 远程 timeout: 180 时一次 bestof* 调用最坏等 ~9 分钟。超时那条进 decision.errors 而非整体 502,其余候选仍正常打分——但你少了一个候选。 prompt 只对远程引擎生效,rapidocr 完全忽略(实测逐字节相同)。

优先级:单次请求 strategy_name > POST /config 运行时覆盖 > config.yaml。新引擎注册即被预设识别,远程侧用 JYKJ_OCR_REMOTE_ENGINES 标记。

引擎个数下限:seq* / cascade* / bestof* 要求至少 2 个已启用引擎,不足直接报错(HTTP 422 / CLI 退出 1),不返回「看起来很正常的单引擎结果」。豁免 local(单引擎部署就是 config.local.yaml)与 vl(保证保留 1 条远程,没有远程则报 ValueError)。下限可用 JYKJ_OCR_MIN_ENGINES 调整(1..99,默认 2),但 bestof* 永不低于 2。强制单引擎(--engine / engine=)不算策略,不受约束。

核心特性

统一端点

设一对 OPENAI_API_KEY/OPENAI_BASE_URL 即可指向任意平台,换平台不改代码。

命名策略预设

local/vl/seq*/bestof*/fallback/quality 四套预设,配置固定默认、请求可一次性临时切换;底层支持 line_overlap/any 窜行降级与 bestof-fluency 语义流畅度择优。seq*/cascade*/bestof* 要求 ≥2 个已启用引擎,不足报 422。

引擎可扩展

新引擎注册即被预设识别;JYKJ_OCR_REMOTE_ENGINES 一键把新厂商划入远程 VL 侧。

运行时配置

POST /config 热改模型/引擎/策略,不重启;线程安全,不回显 key 明文。

惰性注册

import jykj_ocr 不加载 PIL/rapidocr/openai,引擎按需 import。

快速开始

# 安装(自包含 requirements.txt)
pip install -r requirements.txt

# 配置远程引擎(换平台只改这两个变量)
export OPENAI_API_KEY=sk-xxx
export OPENAI_BASE_URL=https://api.siliconflow.cn/v1

# CLI 识别
python -m jykj_ocr image.png --engine multimodal --format json

# 一次性命名预设(窜行降级 + 阅读顺序重排)
python -m jykj_ocr stamp.png --strategy-name quality

# 选用仓库自带的 4 份示例配置(-c 也可用于 serve)
python -m jykj_ocr serve -c config/config.seq.yaml

# 启动 HTTP 服务
python -m jykj_ocr serve --port 8000

HTTP 接口一览

方法路径说明
GET/health健康检查
GET/engines可用引擎列表 + 配置顺序
GET/presets全部命名策略预设(评分模式/重试判定/引擎范围/引擎个数下限 min_engines)
GET/config当前配置(不回显 key)
POST/config运行时覆盖配置
DELETE/config清除运行时覆盖
POST/ocr上传图片/PDF 识别(multipart)
POST/ocr/text按图片 URL 识别(JSON)
POST/ocr/{preset}路由即策略:多部件上传(预设=引擎或策略名)
POST/ocr/{preset}/text路由即策略:按图片 URL(JSON)

实测状态

  • 两引擎在 tests/兰亭序.jpeg(750×1390 中文古文)上全部跑通
  • rapidocr 166 区域,置信度 0.97+,离线可用
  • multimodal 在硅基流动(带厂商前缀模型 ID)与模力方舟(裸模型 ID)两个平台上均返回完整全文
  • 七类命名预设(local/vl/seq*/cascade*/bestof*)在 http://192.168.0.81:8000 实测通过,未知名称返回 400 并列出可选值
  • GET /presets 返回 17 个命名预设 + bestof:<mode> 别名(共 18 项),含评分模式/重试判定/引擎范围/最大重试次数/引擎个数下限 min_engines(bestof*=2,seq*/cascade*=2 可由 JYKJ_OCR_MIN_ENGINES 放宽,vl=1,local=null)
  • 引擎个数下限已落地:seq* / cascade* / bestof* 在只有 1 个已启用引擎时返回 422 并列出实际启用的引擎名,CLI 退出 1;local 与 vl 豁免,强制单引擎(--engine / engine=)不受约束
  • /docs 全部 10 个操作按"OCR 识别"/"配置与状态"两组分类展示
  • 便捷路由 /ocr/{preset} / /ocr/{preset}/text(路由即策略)已上线,新引擎/新预设无需改路由
  • /ocr/{preset} 的路由本身就是策略,不再暴露 retry_mode / score_mode / max_retries(传了会被忽略,不报错);这三个旋钮只在 /ocr 与 /ocr/text 上存在

  • cascade* 家族:被 reject 的尝试立刻降级下一引擎,不重试同一引擎
  • 所有引擎统一走 BaseEngine.recognise 的墙钟超时(rapidocr 与远程),默认 120s,可用 EngineConfig.timeout 覆盖,timeout<=0 关闭
